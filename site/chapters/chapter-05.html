Scope

1. Syllabus Topics

1.1 Main metrics for performance evaluation

Common metrics include elapsed time, throughput, effective bandwidth, speedup, and resource utilization. The right metric depends on whether the objective is total application time, kernel efficiency, or the balance between compute and memory activity.

1.2 Measuring time on the CPU side

Host timers are used for end-to-end timing and can capture preparation, submission, synchronization, and result handling. They are useful when the question is about the total user-visible cost of a computation.

1.3 Using CUDA timers on the GPU side

CUDA events measure time on the device timeline and are the standard way to time kernels or other GPU-side intervals accurately. They avoid confusing CPU submission time with actual device execution time.

1.4 Difference between total execution time and actual kernel time

Total execution time may include allocation, host-device copies, launch overhead, synchronization, and output verification. Kernel time isolates only the interval during which the GPU executes the kernel body itself.

1.5 Analysis of host-device transfers

Transfer analysis separates host-to-device and device-to-host cost from kernel cost. This matters because many early CUDA programs are limited more by data movement than by the kernel itself.

1.6 Identification of bottlenecks

Bottleneck analysis asks which resource is actually limiting progress: compute throughput, memory bandwidth, transfer overhead, synchronization, or application structure. Optimization is only justified after that limiting resource is identified clearly.

2. Guided Exercises

2.1 Timing exercise

  • Measure one workload with a CPU timer and again with CUDA events.
  • State what each measurement includes and excludes.

2.2 Bottleneck exercise

  • Break one program into allocation time, transfer time, kernel time, and total time.
  • Choose the first optimization target and justify it using the measurements.
