Scope

This module follows exactly the second syllabus block, from the definition of CUDA through the first practical vector computation.

1. Syllabus Topics

1.1 Introduction to CUDA as a platform for parallel computing on GPUs

CUDA is NVIDIA’s platform and programming model for general-purpose parallel computing on GPUs. It gives developers a way to express host-device cooperation, launch large numbers of threads, and access GPU hardware through a programming model that is close to C and C++.

1.2 CPU functions and GPU kernels

Host functions run on the CPU and coordinate application logic. Kernels run on the GPU and are executed by many threads in parallel. This distinction is the base of CUDA program design: the host decides what work to offload, while the kernel defines how each parallel thread transforms its assigned data.

1.3 Structure of a simple CUDA program

A simple CUDA program allocates memory, prepares data on the host, copies inputs to the device, launches a kernel, retrieves the results, checks correctness, and finally releases resources. Even the smallest example contains the full lifecycle that later appears in more advanced applications.

1.4 Variables, threads, blocks, and grids

Threads are the smallest logical execution units. Blocks group threads that can cooperate and synchronize. A grid groups blocks belonging to one kernel launch. Variables may live on the host, in device global memory, in registers, or in block-shared memory depending on their intended use and visibility.

1.5 Basic use of the CUDA Runtime API

The CUDA Runtime API provides the core operations needed to write beginner CUDA applications: device allocation, host-device transfers, kernel launches, synchronization, error checking, and memory release. It is the operational layer that turns the conceptual model into an executable program.

1.6 Allocation, transfer, and memory release

In the basic CUDA model, host and device memory are separate. Inputs are allocated on the device, copied from host to device, used by the kernel, copied back to host after completion, and then released. Correct data movement is part of correctness, not only performance.

1.7 First practical example: parallel execution of a simple vector computation

The canonical first example is vector addition. Each thread computes one output element by reading the corresponding elements from two input vectors, writing the result, and using a bounds check when the grid covers more threads than data elements.

2. Guided Exercises

2.1 Implementation exercise

  • Implement vector addition on CPU and GPU.
  • Use the global index formula `blockIdx.x * blockDim.x + threadIdx.x`.
  • Validate results for several vector sizes, including one that is not a multiple of the block size.

2.2 API exercise

  • List the minimum Runtime API calls needed to allocate memory, move inputs to the GPU, launch a kernel, retrieve outputs, and release memory.
  • State what breaks if each call is omitted.
