1. Syllabus Topics

1.1 General structure of a modern GPU

A modern GPU is built as a collection of streaming multiprocessors connected to memory and scheduling infrastructure. Its design goal is high aggregate throughput rather than low single-thread latency.

1.2 Streaming Multiprocessor, CUDA cores, and resource organization

Each SM contains arithmetic units, register files, shared memory, and warp scheduling logic. CUDA cores are part of this internal organization, but useful performance reasoning happens at the level of the full SM resource budget rather than at the level of one core.

1.3 Scheduling of thread blocks

Blocks are scheduled onto SMs as independent units. The hardware decides which blocks can reside on an SM according to the kernel’s demand for threads, registers, shared memory, and scheduling slots.

1.4 Synchronization among threads of the same block

Threads in the same block can cooperate through shared memory and explicit barriers such as `__syncthreads()`. This block-local synchronization model is fundamental because it enables reusable local collaboration without requiring arbitrary global synchronization.

1.5 Transparent scalability of CUDA kernels

Because blocks are independent, the same kernel can scale across different GPU sizes. A device with more SMs can execute more blocks concurrently without changing the source code, provided the problem exposes enough independent work.

1.6 Warps and the SIMD or SIMT model

Although threads are written individually in source code, the hardware schedules them in warps. Threads in a warp progress together through the instruction stream, which is why warp-aware reasoning is central to performance analysis.

1.7 Control-flow divergence

When threads in the same warp take different conditional paths, the hardware serializes the divergent branches. This reduces useful throughput and is one of the most common performance costs in irregular kernels.

1.8 Warp scheduling and latency tolerance

Latency hiding occurs when the scheduler can switch to another ready warp while one warp is stalled on memory or another long-latency event. For this reason, abundant parallelism often matters as much as the speed of one individual thread.

1.9 Occupancy and resource partitioning

Occupancy measures how much of the active-warp capacity of an SM is filled by a given kernel configuration. Registers, shared memory, and threads per block all limit occupancy, so it is a product of resource partitioning rather than a standalone knob.

2. Guided Exercises

2.1 Architecture reasoning

  • For a 256-thread block, calculate the number of warps.
  • Explain what happens when a block size is not a multiple of the warp size.
  • Describe one case where high occupancy may still not produce the best runtime.

2.2 Divergence exercise

  • Write a simple branch inside a kernel and explain why divergence is measured per warp.
  • State how warp scheduling helps tolerate memory latency when many warps are resident.
