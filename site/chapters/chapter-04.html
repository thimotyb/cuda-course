Scope

This module follows the exact topic list of the syllabus memory section.

1. Syllabus Topics

1.1 Memory bandwidth as a performance limit

Many GPU kernels become memory-bound before they become compute-bound. If each useful arithmetic operation depends on expensive global-memory traffic, performance is capped by how quickly data can be moved rather than by how many arithmetic units are available.

1.2 CUDA memory hierarchy

CUDA provides a hierarchy that includes registers, shared memory, local memory, global memory, and specialized read paths. The hierarchy exists because different access patterns need different trade-offs between capacity, latency, and sharing.

1.3 Global, shared, local, constant, and texture memory

Global memory is large and visible across the device, shared memory is on-chip and scoped to one block, local memory usually backs per-thread spill or private storage beyond registers, and constant or texture spaces support particular read patterns efficiently.

1.4 Difference between host memory and device memory

Host memory belongs to the CPU side of the system, while device memory is the GPU-resident global space used by kernels. In the standard model, data must be copied explicitly between them.

1.5 Efficient data access

Efficient access requires arranging data and thread mappings so memory transactions are regular and useful. Poor access patterns waste bandwidth and can destroy the expected benefit of parallel execution.

1.6 Data locality and reduction of memory traffic

Data locality means using data close together in time and space so already-fetched values can be reused. The core optimization goal is to perform more useful work for each byte moved from expensive memory levels.

1.7 The tiling technique

Tiling organizes computation around subregions of the input so threads in a block can stage reusable data in shared memory. It is one of the first major CUDA optimization patterns because it directly reduces redundant global-memory traffic.

1.8 Practical example: matrix multiplication with tiling

Tiled matrix multiplication loads submatrices into shared memory, synchronizes the block, performs partial accumulation, and iterates over tiles. It is a standard example because the value of reuse is easy to reason about and easy to measure.

1.9 Boundary checks in kernels

Boundary checks are required whenever problem dimensions do not align perfectly with tile or block dimensions. They prevent out-of-range reads and writes and are part of production-ready kernel design.

1.10 Impact of memory usage on occupancy

Using more shared memory or causing more register pressure can reduce the number of resident blocks or warps per SM. Memory optimization therefore changes not only traffic but also occupancy and scheduling flexibility.

2. Guided Exercises

2.1 Locality exercise

  • Take a naive kernel and identify which global-memory accesses are reused.
  • State which data could benefit from shared-memory staging.

2.2 Tiling exercise

  • Implement tiled matrix multiplication.
  • Add boundary checks for dimensions not divisible by the tile size.
  • Compare the tiled kernel to a naive one and explain the difference in terms of memory traffic.
