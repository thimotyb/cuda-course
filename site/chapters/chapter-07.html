1. Syllabus Topics

1.1 Choosing block dimensions

Block size affects warp packing, resource consumption, synchronization structure, and total grid shape. A good initial choice is usually a multiple of the warp size, but final tuning must be measured on the target kernel and device.

1.2 Relationship among threads, blocks, warps, and occupancy

Threads are grouped into warps and warps are grouped inside blocks. The number of blocks that can reside on an SM contributes to occupancy, which acts as a proxy for how much scheduling flexibility exists to hide latency.

1.3 Balancing registers, shared memory, and active threads

Registers per thread and shared memory per block constrain how many blocks and warps can be active simultaneously. Tuning therefore requires balancing useful local resources against the desire to keep enough work resident.

1.4 Effects of kernel configuration on performance

Kernel configuration changes runtime because it changes occupancy, memory-access shape, synchronization behavior, and how well the hardware can fill warps. Different kernels react differently, so performance tuning cannot rely on a single universal launch size.

1.5 Practical strategies for testing different configurations

The correct strategy is to sweep valid configurations, preserve correctness checks, and record results with clear device context. Tuning becomes reliable when it is evidence-driven rather than based on folklore.

2. Guided Exercises

2.1 Launch sweep

  • Benchmark one kernel with several block sizes.
  • Record runtime and note any changes in occupancy estimates.
  • Explain the winning choice in terms of resources, not only in terms of the number itself.

2.2 Comparative tuning

  • Compare the best launch configuration for a simple vector kernel and for a tiled kernel.
  • Explain why the same configuration does not need to be optimal for both.
