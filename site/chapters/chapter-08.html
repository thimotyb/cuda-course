M8 - CUDA and PyTorch

Module aligned 1:1 with the syllabus section on GPU usage in PyTorch, `torch.cuda`, tensor movement, and basic memory handling.

Learning outcomes

  • Use `torch.cuda` to inspect device availability.
  • Move tensors and models to GPU correctly.
  • Understand the difference between CPU and GPU execution in PyTorch.

Scope

This module follows exactly the PyTorch syllabus block and translates it into a practical framework-oriented view of CUDA usage.

1. Syllabus Topics

1.1 Introduction to GPU support in PyTorch

PyTorch exposes CUDA-capable devices through its tensor and module abstractions. The framework hides low-level kernel launches, but it still relies on the same device model and memory semantics introduced in the previous modules.

1.2 Using the `torch.cuda` package

`torch.cuda` provides utilities for querying device availability, selecting devices, inspecting streams, and observing memory behavior. It is the operational entry point for CUDA awareness in PyTorch programs.

1.3 Verifying GPU availability

The first practical step is to test whether CUDA is available and how many devices are visible. This prevents incorrect assumptions in notebooks, scripts, and course exercises.

1.4 Moving tensors and models to the GPU

Tensors and modules must be placed explicitly on the chosen device. Correct execution requires that both data and model parameters reside in the same device context.

1.5 Difference between CPU computation and GPU computation

CPU execution is usually simpler to inspect and often better for small or irregular workloads. GPU execution is beneficial when the operation has enough parallel work to justify device launch and memory placement overhead.

1.6 Basic management of GPU memory in PyTorch

PyTorch provides helpers to inspect allocated or reserved GPU memory and to reason about when tensors remain alive. This makes memory behavior easier to observe than in raw CUDA, but the programmer still needs discipline about tensor lifetime and batch size.

1.7 Practical examples of CUDA usage with PyTorch tensors

Typical examples include moving tensors with `.to(device)`, running matrix multiplication on the GPU, moving a model to CUDA, synchronizing before timing, and comparing CPU and GPU runtime for the same tensor workload.

2. Guided Exercises

2.1 Device exercise

  • Print CUDA availability, device count, current device, and device name.
  • Create one tensor on CPU and one on GPU and verify their devices.

2.2 PyTorch benchmark exercise

  • Run the same matrix multiplication on CPU and GPU.
  • Synchronize before reading the GPU timer.
  • Explain at which problem size the GPU starts to make sense.
